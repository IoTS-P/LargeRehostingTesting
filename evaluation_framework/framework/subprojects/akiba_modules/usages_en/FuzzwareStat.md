# FuzzwareStat

## Category

- IoT Firmware
- Fuzzing
- Firmware Analysis

## Description

Analyze Fuzzware fuzzing statistics, including basic block coverage and fuzzer performance metrics.

## Data and Module Interactions

### Configuration File

Configuration file class: `org.iotsplab.akiba.process.FuzzwareStatConfig`

```json
{
  "projectRoot": "fuzzware-projects",     // Fuzzware project root directory name
  "rebaseSource": null                    // Rebase data source (optional), specifies which task data to get base address from
}
```

### Module Dependencies

This module has no explicit module dependencies.

### Database Columns

- 🟢 `total_cov DOUBLE PRECISION`: Total coverage (basic blocks visited by all fuzzer / total basic blocks)
- 🟢 `input_covs TEXT`: JSON-formatted input coverage map, key is fuzzer/trace filename, value is coverage rate
- 🟢 `total_execs_done BIGINT`: Total execution count completed by all fuzzer
- 🟢 `total_execs_per_second DOUBLE PRECISION`: Average executions per second

## Supplementary Explanation

Main functions and working principles of this module:

1. **Core Functions**:
   - Analyze coverage data generated by Fuzzware Pipeline
   - Calculate overall coverage and coverage for each input
   - Collect performance metrics from all fuzzer

2. **Basic Block Coverage Calculation**:
   - Collect starting addresses of all function basic blocks in the program
   - Traverse bblset files in traces directories of all fuzzer under Pipeline directory
   - Parse hexadecimal format basic block addresses
   - Filter addresses that are within mapped executable memory regions
   - Calculate coverage = visited basic blocks / total basic blocks

3. **Performance Metrics Statistics**:
   - Read `fuzzer_stats` file from each fuzzer
   - Extract `execs_done` (completed execution count) and `execs_per_sec` (executions per second)
   - Calculate total execution count and average execution speed

4. **Rebase Support**:
   - Can specify base address from other tasks via `rebaseSource` configuration
   - Use MemoryUtil to relocate memory blocks to match the address space during fuzzing
   - Restore original addresses after analysis

5. **Data Output**:
   - `total_cov`: Ratio of union of basic blocks visited by all fuzzer to total basic blocks
   - `input_covs`: JSON object recording coverage rate for each trace file
   - `total_execs_done`: Sum of execution counts from all fuzzer
   - `total_execs_per_second`: Weighted average speed calculated based on execution time and count of each fuzzer

## Notes

1. **Prerequisites**: Need to run FuzzwarePipeline module first to generate Pipeline directory and related data

2. **Directory Structure Requirements**:
   - Expected directory structure: `{projectRoot}/{id}/pipeline/main*/fuzzers/fuzzer*/traces/bblset*`
   - Each fuzzer directory should have a `fuzzer_stats` file

3. **Memory Filtering**: Only count basic block addresses in loaded and executable memory blocks, ignore invalid addresses

4. **Timeout Setting**: Uses `@IgnoreRuntimeTimeout` annotation, no runtime timeout limit

5. **Application Scenarios**: Used to evaluate fuzzing effectiveness, compare coverage of different input seeds, and analyze fuzzer performance
