# 基地址获取模块 —— EntryFinder

## 分类

- 物联网固件

## 描述

获取一个元素数量尽可能小的集合，其中包含固件可能的入口地址。

## 数据与模块交互

### 临时数据

- 🅞 `List<Function>> entry_point_candidates`: 入口地址的候选集合。

### 提供的 API

- 🟠 `suspend fun updateResult`: 重新获取入口地址的候选集合（函数定义可能发生变化，最终集合可能不同）。

## 补充解释

一个二进制文件的入口地址必须没有任何指向它的交叉引用，因此我们首先可以找到所有没有被其他任何函数调用的函数。然而，由于间接调用的存在，这样的函数数量可能有很多，因此我们需要一些额外的标准来进一步缩小范围：

1. 没有任何返回的函数：入口地址所在的函数绝大多数不会返回，因此我们可以删除那些有返回的函数。
2. 包含函数调用的函数：入口地址所在的函数一定会调用其他函数，因此我们可以删除那些没有调用任何函数的函数。（在函数末尾跳转到其他为止也视为调用）
3. 没有任何参数的函数：入口地址所在的函数一定不包含任何参数（无法传递），因此我们可以删除那些有参数的函数。（Ghidra 深层分析能够推断出函数原型，虽然不能保证一定准确，但 Ghidra 在大多数情况下不会将本没有参数的函数识别为有函数的参数）

在进行上述条件筛选后，最终集合包含的函数数量极少（经过测试发现，包含的函数数量不多于所有函数数量的 1%）。

## 备注

如果入口地址处没有被正确识别为代码并反汇编，最终集合中将没有正确的入口地址。
